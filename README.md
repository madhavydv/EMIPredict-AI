# EMIPredict AI — Intelligent Financial Risk Assessment Platform

A complete, end-to-end financial risk assessment platform that predicts **EMI
eligibility** (classification) and **maximum safe monthly EMI** (regression)
from 22 financial and demographic variables, with **MLflow** experiment
tracking and a **Streamlit** web application for real-time predictions.

Built against the *EMIPredict AI* capstone problem statement (FinTech &
Banking domain, 400K-record dataset, 5 EMI scenarios).

## Results Summary

| Task | Best Model | Key Metric | Target | Achieved |
|---|---|---|---|---|
| Classification (eligibility) | XGBoost | Accuracy | > 90% | **97.8%** (test) |
| Regression (max EMI) | XGBoost | RMSE | < 2000 INR | **₹764** (test) |

Both targets set in the problem statement's "Expected Results" section are met.
Full per-model comparisons are in `reports/classification_model_comparison.csv`
and `reports/regression_model_comparison.csv`, and are also visualized inside
the app's **Model Performance** page.

## Dataset

**400,000** financial profiles across **5 EMI scenarios** (E-commerce
Shopping, Home Appliances, Vehicle, Personal Loan, Education), each with 22
input features spanning demographics, employment, housing, monthly
obligations and credit history, plus two targets:
- `emi_eligibility` — `Eligible` / `High_Risk` / `Not_Eligible` (classification)
- `max_monthly_emi` — maximum safe monthly EMI in INR (regression)

The raw file has realistic data-quality problems (corrupted numeric text,
inconsistent casing, missing values, out-of-range credit scores) that are
cleaned deterministically — see `reports/EDA_Report.md` for the full audit.

## Approach

1. **Preprocessing** (`src/preprocessing.py`) — fixes corrupted numeric
   strings, normalizes categories, clips impossible values, imputes missing
   data (scenario-median for numeric, mode for categorical), removes
   duplicates, and produces stratified 70/15/15 train/val/test splits.
2. **Feature Engineering** (`src/feature_engineering.py`) — 18 engineered
   features: debt-to-income, expense-to-income, affordability & obligation
   ratios, disposable income, a blended credit `risk_score`, employment
   stability, per-capita income, savings ratio, emergency-fund runway, and
   more.
3. **Modeling** (`src/train_models.py`) — trains and MLflow-logs:
   - **Classification:** Logistic Regression, Decision Tree, Random Forest,
     **XGBoost** (best)
   - **Regression:** Linear Regression, Decision Tree, Random Forest,
     **XGBoost** (best)

   Each run logs parameters, metrics (accuracy/precision/recall/F1/ROC-AUC
   for classification; RMSE/MAE/R²/MAPE for regression) and the fitted
   pipeline as an MLflow artifact. The best model of each type (by validation
   accuracy / validation RMSE) is evaluated once more on the held-out test
   set and saved to `models/` for the app.
4. **Streamlit App** (`app.py`) — 5 pages: Home, Data Exploration (interactive
   EDA), Prediction (live classification + regression with a full applicant
   form), Model Performance (MLflow-logged comparison), and a Data Management
   console (browse/filter/add/export).

## Running Locally

```bash
pip install -r requirements.txt

# 1. Train all models (also runs preprocessing + feature engineering)
python src/train_models.py --train-sample 40000

# 2. Launch the app
streamlit run app.py
```

**About `--train-sample`:** this environment's sandbox had a single CPU core,
so the default trains on a stratified 40,000-row subsample of the training
split (validation/test still use their full ~60,700-row allocation each, so
reported metrics are honest). Pass `--train-sample 0` to train on the full
~283,000-row training split — fully supported, just slower on limited
hardware (Random Forest is the long pole; XGBoost scales well). On a normal
multi-core machine, full-data training completes in a few minutes.

To inspect the MLflow UI locally:
```bash
mlflow ui --backend-store-uri sqlite:///mlflow.db
```

## Deploying to Streamlit Cloud

1. Push this project to a GitHub repository (include `models/*.pkl` and
   `models/*.json` — Streamlit Cloud only runs `app.py`, it does not run
   `train_models.py` automatically).
2. On [streamlit.io/cloud](https://streamlit.io/cloud), create a new app
   pointing at your repo, branch, and `app.py` as the entry point.
3. Streamlit Cloud installs `requirements.txt` automatically.
4. Once deployed, the app is available at a public
   `https://<your-app>.streamlit.app` URL.

If your repo needs to stay under GitHub's file-size limits, you can instead
add a `postinstall` step (or a one-time setup script) that runs
`python src/train_models.py` on first deploy — but committing the trained
`.pkl` files directly is simpler and recommended for a 400K-row dataset.
